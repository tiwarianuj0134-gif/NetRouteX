SIDE-BY-SIDE ANALYSIS

Algorithm lab

Run both real routing modes independently against the same topology and client workload.

i

DV and LS execute in separate simulator processes using isolated copies. Route cost is summed from the observed route and actual final active link weights. Metrics the engine does not record are labeled “Not measured.”

⇄Comparison not run

Choose a topology and run both algorithms to compare real output.

DV

Distance Vector

Each router shares its known destination costs with direct neighbors. Routers update a next hop from the neighbor advertisement plus link cost.

Core ideaDistributed neighbor updates (Bellman–Ford recurrence)
LS

Link State

Routers flood numbered link descriptions. Each router builds a weighted graph and asks NetworkX for the shortest path.

Core ideaTopology graph plus weighted shortest-path calculation

Measurement notes

How to interpret this report.

  • Delivery ratio = delivered observed client pairs ÷ observed client pairs. Shown as “Not measured” when no pairs are present.
  • Average hops and average route cost use delivered paths only.
  • Route cost sums directional costs along the actual observed path using the final active link set.
  • Simulated latency, convergence time, and routing update counts are not measured by the current engine.
  • Wall-clock runtime is process duration only; it is not packet transit latency or simulated time.
GETTING STARTED

Quick guide

A beginner-friendly guide to the simulator and its controls.

01

Load a topology

Choose one of the JSON examples or upload a topology file. The backend validates node names, links, ports, costs, events, and expected routes. Uploads are kept in memory and are not saved over your files.

02

Run a simulation

Select DV or LS, then choose a client source and destination to spotlight. The Python engine still runs its client-pair traceroute workload. The shown path comes from actual packet callbacks.

03

Compare modes

Comparison runs DV and LS separately on validated copies of the same topology. This avoids sharing router state. Route paths, hop counts, and costs are derived from returned simulator results.

04

Test a link failure

Choose a router-to-router connection and inject a time-zero link-down or link-up event into a fresh experiment copy. Existing configured topology events are retained.

Networking terms

Simple explanations for the project presentation.

RouterNetwork node that forwards traffic to the next hop.
GraphNodes represent devices; weighted edges represent links.
Link costDirectional weight used to compare routes. In the current simulator it also influences link delay.
Next hopThe adjacent node/port selected for forwarding.
Distance VectorRouters learn destination costs from their neighbors.
Link StateRouters flood link descriptions and compute paths over a graph.
Packet forwardingA router reads a packet destination and sends it on the selected outgoing link.
UnreachableNo packet route reached the selected destination in that simulation.
Educational scopeThis project does not send real network traffic and is not a complete or standards-compliant RIP/OSPF implementation.
